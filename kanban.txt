Ce que ça devrait être (logique RH)

Dans un ATS, le Kanban est le pipeline de recrutement : chaque carte = un candidat pour un poste. Glisser une carte de "CV reçu" vers "Entretien RH" devrait mettre à jour application.status. La page candidatures elle-même a déjà les statuts EN_ATTENTE / EN_REVISION / ACCEPTE / REFUSE, mais dans une vue liste.

Recommandation

Deux options :

Option A — Lier le Kanban aux candidatures (correct pour un ATS)
- Ajouter candidatureId String? sur KanbanCard (ou supprimer KanbanCard et utiliser Application directement comme carte)
- Les colonnes Kanban deviennent les statuts du pipeline
- Quand on déplace une carte → mutation.mutate({ applicationId, newColumnId }) met à jour Application.status
- Les cartes s'auto-créent quand une candidature arrive (ou le recruteur les importe depuis la page candidatures)

Option B — Garder le Kanban séparé, clarifier l'UX (plus simple à court terme)
- Renommer en "Tableau de bord projets" ou "Suivi de tâches" pour éviter la confusion
- C'est utile pour gérer des tâches de recrutement (sourcing, relances), pas le pipeline candidats
- Mais dans ce cas, la page Candidatures reste la source de vérité

Je recommande l'Option A car c'est ce qu'un recruteur attend naturellement d'un "Tableau Kanban" dans un ATS — voir ses candidats par étape de recrutement. Aujourd'hui le Kanban n'a pas de valeur réelle car aucune candidature n'y atterrit automatiquement.
